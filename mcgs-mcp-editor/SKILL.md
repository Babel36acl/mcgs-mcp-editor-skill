## 解析与修改

1. 以本次指定的磁盘文件为准，先记录文件 SHA-256、版本、窗口 ID、记录索引及完整 payload 哈希。按文档头、计数、记录长度和 trailer 定界；字符串扫描仅用于发现线索。解析失败单独报告，不能跳过异常后称“零控件”或“全部通过”。
2. 修改前核对当前命令是否支持该操作，以及目标记录是否符合已查证布局。相同 kind、相同长度或坐标看起来合理都不能单独证明布局一致。未知记录可以原样保留，不得猜偏移修改。
3. 编辑清单使用修改前 payload 的偏移、预期旧值和精确哈希。变长字段同步所有已查证的覆盖长度；多项比较先对齐字符串和嵌套边界。输入框绑定同时修改名称和对象 ID，范围顺序是 `[最大值, 最小值]`。名称修改另查重复名称和引用。
4. 标准按钮事件的源码和编译数组一起生成、一起替换。脚本仅支持当前数值子集；符号 ID 必须由该工程查证，不能用名字排序或其他工程的索引代替。
5. 写入新路径并保留原件。回读全部非系统表，确认实际变化等于声明的变化，保留未解释字段、编译标志和窗口 trailer。只读检查另列窗口行与尾部身份是否一致；已定位的导航名/ID 用精确哈希引用清单检查。哈希或原值不匹配时停止该字段编辑，补充取证；不做全局字符串替换或删除未知块。

## 验证与能力边界

- 区分数据库/完整记录回读、合成测试、原厂机器码仿真、宿主操作和真实设备结果。检查工具的 PASS 只覆盖其实际规则；保留失败项、跳过项及总分母。
- 修改后的宿主验收按功能执行：打开、属性、Ctrl+E、离线输入/动作、保存关闭重开。输入框测范围内及越界值，条件脚本覆盖真假分支。同一产物的操作者确认可作历史宿主证据，写明具体操作及文件哈希；后续改动须重新关联证据。
- 目前登记 22 类；正式 `rectangle` 只支持六类。另有 `horizontal_move` 仅支持 5004/5006 两份已验样本的特征匹配，锁定尺寸、纵坐标、样式、名称及其他字节；不按类型/长度通用放行。0x5026 暂无可写字段；0x5030 未登记。0x5039 的动作位仍待单项对照，不能直接套单样本配方。
- 同窗口克隆及模板窗口复制已有入口，但不代表跨窗口引用、全局对象 ID、资源归属或删除清理已解决。新变量和设备通道没有 CLI 创建入口；新地址使用宿主原生流程，不能复用已出现静默丢弃的字节新增方案。
- 厂商二进制由使用者提供。原厂仿真按版本哈希锁定，数据对象映射到内存，不访问真实设备。宿主 UI 受限时继续可执行的文件侧工作并列明具体未验项，不修改系统权限绕过隔离。

## 维护本技能

运行依赖分三档：`inspect` 只需 `access-parser`；`patch` 额外需要 Windows + 与 Python 位数匹配的 Access ODBC 驱动（不是 pip 包，须自行安装）；原生编译/仿真需要 `pefile`+`unicorn` 与用户自备的厂商二进制。详见仓库 README「依赖与驱动」。

在技能的源码仓库修改并验证，再同步已安装副本；安装目录只作为发布副本，避免多处独立演进。同步前保留可恢复备份并核对文件清单及 SHA-256。发布材料仅含原创工具、格式事实和合成测试；真实工程、截图、厂商程序和原始反编译资料留在用户工作区。外部发布、持久记忆同步及真实设备动作仍按本次用户授权范围处理。
