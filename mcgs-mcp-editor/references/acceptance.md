# 验收及 V1 损坏复盘

以下是 2026-09-07、McgsPro 3.5.1.7267 下实验副本的证据，不包含用户工程、截图或厂商二进制。

| 能力 | 实际证据 |
| --- | --- |
| 标签改为不同长度中文 | 用户检查属性和页面显示通过 |
| 数值输入框改绑、范围 | 用户确认绑定及上下限正确；离线输入范围内值写入目标变量，越界值被拒绝或限制；反馈未区分拒绝和钳位 |
| 按钮事件替换 | 用户确认打开、Ctrl+E、点击写入新值通过 |
| 保存关闭重开 | 用户补验通过，磁盘回读绑定和范围仍正确 |
| If/Else 条件脚本 | 原厂代码生成与解释器仿真通过，用户确认实际连续点击在两个数值间交替，保存关闭重开仍正常 |
| 源码与字节码 | 原有嵌套 If 脚本通过新生成器重新生成，95 字节与既有宿主字节码完全相同；新条件脚本宿主验收后回读 57 字节也未改变 |

宿主证据是用户对列明步骤的确认，不是本工具生成的自动 GUI 轨迹。没有连接控制器或进行整机验收。

公开打包回归：6 项合成结构/字段测试、3 项原厂代码生成测试通过。公开工具在本地私有副本上的标签、输入框和条件按钮输出，与宿主验收后 payload 逐字节一致。按钮改字输出与已验收 B 的精确打开前输入一致；B 保存后另有一个尚未解释的属性字节变化，工具保留该字段，不猜测其含义。

## V1 根因

失败版本同时改了事件源码/字节码、两份按钮 caption，以及 `iCompileFlag`，宿主提示“工程已损坏”。外层记录和 Access 数据库回读正常不能证明内部对象可用。

第一份 caption 从 6 个 UTF-16 单元变成 4 个，少了 4 字节。它在三个嵌套数组中，原写入程序漏更新了这些 u16 长度。第二份 caption 在这三个数组之外。失败样本中的偏移及修复：

| payload 偏移 | 原值 | 修复值 |
| --- | --- | --- |
| 94 | 461 | 457 |
| 106 | 449 | 445 |
| 108 | 445 | 441 |

内层数组的边界因此整体移动 4 字节；不能按未更新计数继续读取后续事件数组。`CDrawButton` 基类将附加属性保存为嵌套 byte array，然后再以子 CArchive 读取按钮样式，原生序列化调用链支持这一解释。

最小对照：

1. 从已通过版本仅把 `iCompileFlag` 由 1 改成 0，打开正常。
2. 从报错 V1 仅修这三个长度，保留 V1 的文字、脚本及编译标志，用户确认打开无提示，caption/属性、编译、保存关闭重开正常。

因此，该 V1 的损坏根因是漏更新嵌套长度。此结论没有证明“编译标志可以任意修改”；公开工具仍保留它，因为当前功能无需修改。

这三个偏移只属于原实验 payload。其他模板需要重新建立边界和原值，不能用它们作为通用补丁。公开工具使用显式 `nested_counts` 清单，按真正包含的变长编辑累加差值。

## 每个新模板的验收

数据库差异与完整记录回读 → 控件属性 → Ctrl+E → 离线值/事件验证 → 保存关闭重开并重复。输入框至少检查范围内值与两端越界值；条件按钮覆盖真假分支。相同模板的批量生成可以复用格式证据，但不能省略生成结果、重复名称及实际变量映射检查。
