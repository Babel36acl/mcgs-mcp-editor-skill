# 多方向验证与取证

## 按产物组织证据

为本次输入和输出记录文件 SHA-256、软件版本、窗口 ID、记录索引、类型、完整 payload 哈希及操作。保存后再次读取哈希；文件名不变不代表产物未变。历史会话和截图只证明其中实际发生的操作，不能将“没报错”升级为全部行为验收。

| 证据层 | 应检查 | 不能代替 |
| --- | --- | --- |
| 数据库 | 所有非系统表、行/列、BLOB 差异 | 控件内部结构或宿主加载 |
| 完整窗口记录 | 文档头、记录数、长度边界、trailer、其他记录原样保留 | 内部嵌套字段和运行语义 |
| 字段/引用 | 修改前哈希、原值、嵌套长度、绑定名称/ID、导航与资源 | 宿主编译及保存持久化 |
| 测试/原厂代码仿真 | 正向行为及错误输入拒绝，报告跳过项 | 原生 GUI、设备和现场结果 |
| 宿主 | 打开、属性、Ctrl+E、相关动作、保存关闭重开 | 下载或真实设备验收 |

普查需同时输出文件数、窗口总数、完整解析数、拒绝数和失败原因。记录数量只统计完整解析窗口；诊断得到的局部记录另列，不混入完整覆盖。`mcp_tool.inspect` 的 `summary` 与 `complete` 可用于此分母，不能只统计 `records` 键。

`references` 是另一层结果：当前自动检查窗口行/尾部身份与名称、ID 唯一性；通过精确源文件/控件哈希和显式字段位置检查导航。名称/ID 必须共同指向唯一窗口；未知尾部不按相近整数猜解。名称与 ID 不一致、模板复制残留旧身份等只报告，不自动修补。变量、资源和未标注导航仍明确列为未覆盖。`--require-complete` 管窗口记录，`--fail-on-reference-mismatch` 管已检查引用的不一致，两者不能代替全部工程验收。

## 已知统计陷阱

2026-10-17 安装目录的 18 份样例共有 143 个窗口，当前解析器完整读取 136 个、拒绝 7 个，成功窗口合计 **4099 条、21 类**。历史总结的 3799 与原始工具输出不符。成功部分未出现 5030/5026，不代表被拒绝部分或全部合法工程不存在这些类型。

旧版包的 17 文件、132 窗口全部未通过当前完整解析器。历史脚本在窗口层吞掉异常，将数据库成功错误地表述为“0 个失败、0 控件”。其中 87 窗口可走完声明记录，后续 trailer 规则不匹配；这只是诊断前缀，不是已经支持旧版，也不能据此宣称格式整体完全不同。

## 与其他实现对拍

先检查其实际规则和底层依赖。两套工具共用数据库解析库时，数据库层不是完全独立证据。把未知字节作为 GAP 保存可实现 100% coverage，但不说明记录计数、长度或字段语义正确。

曾将一个 18,371 B 窗口的首条 payload 长度在内存中改为 65,534 B：严格解析器报截断，另一实现的窗口 coverage 仍报 100%。此反例只针对 coverage 规则，不声称整套检查对该坏输入均通过。可用临时内存负例验证越界长度、缺失记录和错误 ID 的拒绝行为，不将坏文件交给宿主或设备。

对变量解析器的连续 ID 假设，应使用原生删除后再新增样本检查；对页面尺寸校验，应区分弹窗/键盘与主页面；对未知图片信封应报告兼容缺口。第二验证器失败不自动等于工程损坏，PASS 也不自动等于功能完整。

第三方实现中有价值的只读线索包括：窗口 trailer 自 ID、导航名称/目标 ID、ObjData 计数、策略双存储、图片清单及资源引用。先在完整记录边界内验证这些关系；未经边界验证的全 BLOB 扫描只算候选。外部 builder 的完整供体设备注入或已有通道换绑不能证明新地址注册成功。

## 逆向分析的边界

- 区分宿主构造器、文件 Serialize、内存对象和运行时下载流。构造器中的 kind/虚表可识别类型，不能代替 Serialize 读取路径。
- `operator_new` 是内存分配尺寸；文件中的长度由实际读写操作定义。虚函数读取的子对象不能凭内存尺寸简化为固定二元组。
- 变长结构可以出现等长实例；无同长样本只说明当前样本不足。优先组合原生单字段差分、静态读取顺序、完整流消耗量和宿主往返。
- 区分导出表、内部符号/RTTI、普通字符串和反编译推断名；同一插件可能包含多个类型。读取路径中的条件分支应核对每次 Read，不只采用摘要。
- `CD CD` 与调试堆填充相关，但任意文件字节出现它并不能证明该字段未初始化。仅在确切读取分支中解释哨兵值。

相关原理：[Microsoft 持久化格式](https://learn.microsoft.com/en-us/cpp/mfc/tn002-persistent-object-data-format?view=msvc-170)、[CRT 调试堆](https://learn.microsoft.com/en-us/cpp/c-runtime-library/crt-debug-heap-details)。这些资料不定义 MCGS 的私有格式。

## 最小原生对照

按实际任务选择一组，不默认要求用户执行所有实验：

- **几何**：从同一模板仅移动目标，另一个独立副本仅改宽。确认完整记录、字段宽度、原值、属性和保存结果；移动通过不自动证明缩放。
- **5039 动作**：从同一基线分别只打开目标窗口、只退出运行、只置1到明确的离线变量，再分别取消。比较目标记录、同窗其他记录、语言表和资源表；三项联合样本用于组合对照，不能逐位命名。
- **变量**：新增 A/B/C、删除 B、再新增 D，各步保存；另做改名/改类型及已有控件或通道换绑，查 ID、计数和引用。
- **通道**：与失败样本保持相同驱动、区、数据类型、地址及宽度，走宿主原生新增，再重导 CSV 和回读设备 BLOB。不同区或类型的成功不能当等价对照。

本地证据清单可记录输入/输出路径及哈希、软件版本、操作、字段差分、宿主反馈来源和待验项。公开技能只保留通用格式事实与方法，不携带原始工程、截图、厂商文件或反编译输出。
