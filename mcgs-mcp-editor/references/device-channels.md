# 通道加载与验证边界

适用于 McgsPro 3.5.1.7267 下的工程装配、变量与设备通道分析。以下归纳 2026-10-14 至 16 的历史实验及 2026-10-17 文件回读；只发布格式事实和证据摘要。原始对话、工程、截图、厂商程序及反编译清单不随仓库分发。

## 能力与证据

| 操作 | 已有证据 | 使用边界 |
| --- | --- | --- |
| 画面数值输入框改绑到现有变量 | 属性、离线输入、保存重开验收 | 使用已经查证的名称和对象 ID；不创建变量或通道 |
| 新窗口 | 模板克隆后 26→27 窗口，宿主打开、Ctrl+E、保存重开通过 | 只证明模板窗口行复制；不证明跨窗口引用或全局 ID 分配 |
| 同库内设备通道改别名、换绑定 | 后续审查明确列为未测 | 只能作为实验候选，需宿主保存重开及重导 CSV 对照 |
| 字节新增或改名为新地址 | 实验记录被宿主静默丢弃，保存后整条删除 | 不作为支持能力交付；新地址走宿主原生增加设备通道 |
| 宿主原生新增通道并填写连接变量 | 最小装配历史验收记录通过 Ctrl+E、保存重开、重导 CSV；当前文件仍含对应通道及变量名称 | 仅限该原生操作路径和样本；当前文件后续已编辑，旧验收不覆盖其全部控件 |
| 任意新变量、其他驱动或区的通用创建 | 没有完整端到端证据 | 不从单设备样本推导通用生成规则；CLI 无此入口 |

## 后续审查修正了什么

早期实验用字节克隆新增一条通道，计数和变量关联在文件侧对齐。后续检查发现，候选 4 区地址 35 已被地址 34 起始的 32 位记录覆盖；另一个地址 38 起始的 32 位记录也覆盖地址 39。计算空闲地址必须计入类型宽度，不能只比较记录的起始地址。这里观察到先占用记录排斥冲突记录的现象，不能据此实现跨驱动的通用冲突算法。

候选改到样本中无占址冲突的 4 区地址 152 后，宿主仍不显示该记录。回收对话记载：三次重导 CSV 均为 230 条且没有候选记录，也没有报错弹窗；保存前后 `WndDevice.lbObjects` 从 27664 缩至 27591 字节，恰好减少 73 字节。后续原生对照新增的是 **1 区地址 152**，不能当成相同区、类型、地址的成功对照，也不能把不同来源文件的 blob 长度直接相减来复现这项历史差值。

这些观察证明了该样本中字节新增路径会失败。静态追踪支持丢弃发生在加载和通道名称解析/注册阶段，而不是列表显示或 CSV 导出阶段。驱动地址库或注册状态参与校验是当前解释；具体注册数据结构未完整映射。地址 151 是该样本的观察边界，不能写成所有 Modbus 设备或所有 MCGS 工程的固定上限，也不能声称所有字节新增组合均已实验否定。

需要新地址时采用宿主原生“增加普通通道”或对应驱动提供的增加通道流程。不要继续靠改后缀、补计数或修改唯一序号来尝试绕过已观察到的加载丢弃。

## 原生最小装配样本

ModbusRTU_串口、构件版本 7.101 的样本在宿主新建设备后自带 8 条 1 区地址 1–8 的默认只读通道。CSV 中这些默认通道无连接变量，变量类型为 INTEGER，数据类型列为 NULL。它们属于该驱动/模板的观察结果，不能预设所有新设备都有相同默认项；规划点表时先读取实际通道，已有匹配项考虑复用，新增项按类型宽度检查重叠。

随后通过宿主原生操作新增四条：0 区 BIT 地址 10、1 区 BIT 地址 152、4 区 WUB 地址 100、4 区 DUB 地址 110。BIT 的 CSV 变量类型/数据类型为 INTEGER/NULL，WUB 与 DUB 均为 SINGLE，数据类型列分别为 16 位/32 位无符号二进制。这里的 SINGLE 是宿主变量类型标签，不能据此将 WUB/DUB 的寄存器编码解释成浮点数。DUB 占用地址 110–111。

历史验收记录称填写连接变量时宿主自动建立四个同名变量，Ctrl+E、保存关闭重开及重导 CSV 通过。2026-10-17 对现存文件的只读检查确认：通道计数为 12，CSV 有 12 条数据行，四个连接变量名分别出现在设备通道与 `System` 表的变量存储中。该文件在历史验收后又增加了控件和资源；应记录当前哈希，不能把旧验收套到当前完整工程，文件回读也不能独立证明自动建变量的操作过程。

设备及驱动标识应从解析后的设备 BLOB 和 CSV 元数据交叉核对。本次样本两处的驱动文件名均为 `modbusrtuex_str.ui`；没有支持“一定存在 .uid/.ui 差异”的当前证据。Access 文件绝对偏移会随保存变化，不能当作 `WndDevice.lbObjects` 内偏移使用。

## 记录线索与未验证项

- 已检查的工程在 `System` 表中 `strName=ObjData` 行的 `lbContext` 保存变量相关对象，在 `WndDevice.lbObjects` 保存设备通道；`System.ObjData` 是这条系统记录的简称，不是实际列名。其他业务表为空只是样本事实，不能作为通用格式定义。
- 已对齐的 4 区通道记录包含名称、别名、角色字符串、空字符串及尾部字段。别名参与变量关联，通道名后缀参与地址解释；不能只改一个数字 ID 就认为绑定或地址已更新。
- 一个 73 字节记录布局含尾部首 dword `A`；231 条记录样本中 `A` 无重复。部分其他记录尾部长度不同，类型语义尚未完整映射。唯一性检查通过仍不足以使合成记录通过宿主加载。
- 1 区曾观察到 47 字节记录，4 区曾观察到 73–85 字节记录。不能跨区套用整条布局或固定长度，也不能将这些长度视为全部合法长度。
- 变量序号复用删除空洞、`A = 变量序号 + 1` 等规则只有单项目或单设备线索，未建立通用分配算法；早期相关候选还受到后续 purge 结论修正。不要据此添加任意变量创建功能。

## 新工程或通道变更的工作路径

1. 从用户选定的原生模板复制新文件，记录模板哈希与设备/驱动版本。不能用空 Access 数据库替代原生工程模板。
2. 列出需求的区、类型、起始地址、地址宽度和别名，与模板已有通道逐项对照。无法确认宽度或存在冲突时先补原生对照。缺少通道时给出原生增加清单，由有授权的宿主操作完成。
3. 通道在宿主中确认后，再核对实际变量及画面对象绑定。宿主填写连接变量可能自动建立变量，仍需回读确认名称和类型，不能把该行为推广为字节创建规则。当前 `mcp_tool.py` 仅编辑窗口控件和复制模板窗口，没有变量/设备通道写入接口。
4. 将数据库回读、宿主打开、保存关闭重开、重导 CSV 分开验收。通道应按区、类型、地址及别名对照，行数相同也可能有替换或丢失；同时回读保存后的通道 blob。遇到静默丢弃，应保留前后证据并停止该字节新增路径。

CSV 样本使用 GBK，前四行元数据、第五行表头；宿主界面序号从 1 开始，CSV 通道号从 0 开始。这些是样本观察，处理新导出时应先检查实际编码、表头和编号，不按行号猜测缺失通道。
