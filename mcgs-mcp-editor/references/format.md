# 格式与支持边界

## 数据库与顶层记录

MCGS 的 `.MCP` 在已验证工程中为 Access 数据库；不是 JSON 协议文件。`WndUser` 按 `iID` 标识窗口，控件主要放在 `lbObjects`。其他表、编译标志和未解释字段必须保留。

最初在 36 个原生窗口、771 条记录上验证以下结构；后续样例普查的扩大范围与拒绝项见 [验证与取证](validation.md)：

| 位置/字段 | 编码 |
| --- | --- |
| 开头 12 字节 | 未完整解释，保留 |
| offset 12 文档标识 | CArchive 字符串 `MCGS-SET DOCUMENT;VERSION 01.00` |
| 标识之后 | u32 控件记录数 |
| 每条记录 | u32 类型 + u16 payload 字节数 + payload |
| 计数记录之后 | 原样保留 trailer；已识别样本满足首 u32 + 10 = 剩余长度 |

类型 `0x5008` 为标签，`0x5025` 为数值输入框，`0x5027` 为标准按钮。类型值不是对象 ID。记录长度达到 65535 的扩展编码尚未实现，必须拒绝。

当前只读身份检查在严格窗口记录结束后读取 trailer；已观察前缀含 `u16(3) + u32 窗口ID + u16(8) + u32 名称字节数 + UTF-16LE 名称`，ID 位于 trailer +12 或 +14。通过标签和有界名称定位布局，再与行字段比较，不以“两个位置任一个值碰巧等于行 ID”来选择布局。未知或歧义前缀标为未覆盖，发现不一致只报告、不自动修补。该字段检查不定义整个 trailer 序列化。

下拉框 498 B 同长组中名称字符串曾观察于 +78；同 kind 的其他长度或布局需要重新查证。0x5039 的样本可在动画组态中配置按钮动作，这只说明该样本的功能，不代表所有单元格都是相同的按钮或可套用同一配置位。

原生报表实验出现 `0x5030`，尚缺构造映射及完整单元格序列化证据，当前不登记、不允许显式编辑。官方样例成功解析部分零命中不能证明没有该类型；完整普查的成功/拒绝分母见 [验证与取证](validation.md)。顶层未知记录在结构完整时可以读取和原样保留。

### 0x5026 CDrawFlow：身份与布局分开判断

2026-10-17 第三方样本有 3 条 0x5026（413/391/397 B）。宿主构造器 RVA 0x389350 / 0x389520 的指令在 RVA 0x389376 / 0x38954a 推入 0x5026，再安装相同的虚表，支持类型身份。旧版 `draw_flow.dll` 含该常量及 CDrawFlow/FlowCode/express 等内部字符串；其导出表是插件入口和 RTTI 项，不能写成“导出名就是 CDrawFlow”。

三条记录含条件字符串与尾部成对 int32。尾部候选计数为 10/6/8，满足 `333+10×8=413`、`343+6×8=391`、`333+8×8=397`；中间一条字符串比另两条多 5 个 UTF-16 单元，贡献 10 B 长度差。数值形状支持坐标点候选，尚未证明是步序表或动画数组。

旧版插件 `CDrawObj` 基类的流读取显示事件数组与按 0x3001–0x300B 分派的动画子对象，但当前 MCP payload 与该运行时流未建立完整映射，不能直接按此编写文件解析器。尤其：bit8 分支实际读取 **两个 4 B 字段再读 CString**；内存分配大小不是序列化长度；基类读取不是派生类型文件结构的全部。

**当前拒绝编辑的原因是字段、布局及完整序列化路径未验证。** 变长结构仍可能出现等长实例，不存在“本 kind 永远不可能有等长样本”的依据。后续结合宿主实际读写路径、同基线单字段差分、完整 payload 消耗及保存重开建立证据，再讨论受限放行。

## 剪贴板与 MCP 记录的对应关系

已对照样本中，剪贴板 `MCGS_DRAW_OBJ_PRO1` blob 与 MCP 控件 payload 的字段位置相差 18 字节前缀。两条独立标签记录的块结构一致，但另有一处 2 字节长度差，不能直接宣称整个 blob 去头后逐字节相等。9 月剪贴板矩形偏移 `0x1E` 换算 MCP 为 +12，与已验收标签样本一致。该换算用于复用已有单字段差分线索；应用到其他记录前仍需核对类型、边界及预期原值。

## 文档头兼容性与虚表否定结论

文档标识接受 `MCGS-ESET DOCUMENT` 与 `MCGS-SET DOCUMENT` 两种前缀，均要求 `VERSION 01.00`（原厂文档 Serialize 反编译证实）。解析器目前只接受 SET 变体；遇到 ESET 变体应明确拒绝而不是猜解。

已检查的五类控件虚表各 24 槽中，类特有槽未发现 CArchive 存取入口，17 槽为返回 0 的基类桩；检查过的 56 组 ReadCount/WriteCount 函数呈通用 MFC 容器模式，未发现 kind 常量引用。这支持优先追踪窗口容器层和原生单字段差分，尚不能当作所有类型的序列化器已定位或字段已通解。

## 字符串与字段

CArchive Unicode 标记为 `FF FE FF`，后面是字符数量：通常 u8，255 转 u16，65535 转 u32。长度单位是 UTF-16 code unit，不能直接使用 Python 字符个数。阅读器也识别 ANSI 字符串，默认 GBK。写入工具支持 Unicode 长度小于 65535。

标签、输入框、按钮已识别样本的矩形分别位于 payload +12、+24、+24，下拉框样本为 +24，存储 `(left, top, right, bottom)` 四个 int32；DLL 控件存在 +12 和 +24 两种样本。这些是取证线索，不是对所有版本或相同 kind 的偏移保证。控件名称长度变化会使后续偏移移动。

一个经宿主验证的数值输入框在绑定名称字符串结束处紧接两个 float32，依次为 maximum、minimum。已验证文字长度变化、现有变量改绑及范围变更；其他格式、键盘、安全属性未完整通解。

该输入框在绑定名称起点前 8 字节另存 u32 绑定对象 ID。只改名称时，原实验由宿主编译更新该 ID；保存重开验收后的差异发现并确认了此字段。公开工具的 `input_binding` 同时修改名称和已查证的 ID，输出与宿主验收后的 payload 一致。ID 与 ObjData 存储索引的关系需逐项目验证，不能从名称排序推算。

按钮 caption 中 `U+0007` 前缀可表示多语言引用；普通可打印字符串扫描会跳过它，必须用精确偏移 `read_string`。文字、背景图、字体的缓存及原生成员可能出现多份。不要把命中的字符串都视作独立字段。

## 按钮源码和字节码

已逆向的 `CDrawButton` 原生成员：第一事件源码 +0x208、数组 +0x210；第二事件源码 +0x228、数组 +0x22c。成员偏移是内存布局，不能直接当作文件偏移。第一事件的编译数组在基本动画块之后，第二事件源码和数组在记录尾部附近，序列化顺序不同。

已验证短字节数组用 u16 计数；不是 u32。字节码有 12 字节头部（三个 u32），当前无参数/局部变量子集写零；最后为返回指令。样本末尾另有 6 字节安全属性，必须保留。修改源码而保留旧字节码会导致显示逻辑与执行逻辑不同。

工具构建受限 AST，执行原 EXE 中 `SyntaxBlock`、`SyntaxSelect`、比较、加法、赋值生成器和缓冲区写入代码。分支位移由原厂代码回填。完整原生词法/语法分析器和工程编译器没有调用。

运行仿真执行 `script.dll` 内原解释器；数字数据读写映射至 Python 字典，其他宿主能力未实现。解析入口与执行循环已静态定位，但工具仍只支持已实现的数值指令子集；观察到更多 opcode 不等于具备完整 BASIC 能力。已检查的导入与调用路径支持现有受限内存复制白名单；这不构成 DLL 整体安全结论，也不允许扩展到真实设备 I/O。该工具使用版本锁定的虚拟地址，文件不匹配则拒绝，不能通过改哈希绕过兼容检查。

## 变量与设备通道

变量存储、画面绑定和设备通道是不同层次；已验收输入框绑定修改不能作为新变量或新通道创建的证明。设备通道存在数据库可读但宿主加载丢弃、保存删除的实证。涉及这些操作时读取 [通道加载与验证边界](device-channels.md)，不要沿用早期通道克隆成功的结论。
