# 变量 ID、类型与引用状态

适用于变量表取证和同一原生模板的删增实验。这里记录受限布局及实际证据，不提供任意变量创建或通用 ObjData 序列化能力。

## 第三方资料与当前版本

[MCGS_File_Create](https://gitcode.com/linjian19901122/MCGS_File_Create) 提供 ObjData、设备绑定及工程装配的对照实现。2026-10-17 核对提交 `fddc2155edb95b84fa5257184e490f54e7948b35`，40 个跟踪文件与本地下载包逐字节一致，仓库没有随附原生验收 MCP。[变更记录](https://gitcode.com/linjian19901122/MCGS_File_Create/blob/main/mcgs-tools/CHANGELOG.md) 的工具版本为 0.1.0、格式绑定 3.5.2.12210；本技能当前宿主是 3.5.1.7267。按具体字段和实际样本验证兼容性，不移用其他版本的全工程验收结论。

来源解析器从 expected=0 逐条寻找连续 ID，追加使用记录数作为新 ID。它能读某些连续 ID 工程，不证明宿主在删除后会复用空洞、重排 ID 或总是从末尾增加。不能用该解析器的输出再反证其连续 ID 假设。

## 已核对的受限结构

数据位于 `System` 表中 `strName=ObjData` 行的 `lbContext`。以下偏移都是该 BLOB 或其已定界块内偏移，不能直接写入 Access 文件绝对位置。

- 头部 12 B：当前样本前 4 B 为 `00 00 40 41`；+4 的小端 u32 等于 BLOB 长度减 8；+8 在完整走通的样本中等于记录数。
- 一种已对上的记录布局：三个 tagged UTF-16 字符串、36 B 块、一个字符串、28 B 块、初值字符串、36 B 尾块、末尾字符串。必须逐项校验边界、完整消耗及头部计数；不要靠寻找预期 ID 定界。
- 此布局的尾块 +12 保存实际对象 ID，+16 是引用状态候选。中间 28 B 块的 +12 **不是这些记录的自身 ID**：基线四条记录那里都是 10，自身 ID 分别是 0/1/2/3；新增的那条记录那里是 0，自身 ID 是 4。
- 2026-10-17 对照若干副本，其中 6 个完整符合此受限布局，实际只有 4 种不同 ObjData 内容，重复副本不算独立结构证据。另一份含 816 条声明记录的试验工程只确认前 130 条，后续布局拒绝并保留 100902 B 未解析；不能将该失败归因为已确认的 ID 缺号或工程损坏。

这些事实只供字段定位和只读交叉检查。类型、报警和扩展尾部存在变体，未匹配时停止该布局解析，不扫描后续同名字符串来补齐记录。

## 原生新增一个变量的当前证据

同一模板四条内建对象 ID 为 0/1/2/3。无修改另存后，全部非 MSys 表相同；随后新增一个整数变量、初值 0，只有 ObjData 单元格改变：660→798 B，计数 4→5，追加 138 B，原四条记录逐字节不变。新增记录 ID=4，类型码=1，引用状态候选=0。

输入与输出产物的 SHA-256 只记录在本地取证目录，不随仓库分发。这只证明该模板的首次新增，不证明删除后的分配或绑定更新；原始文件与截图同样留在使用者工作区。

类型叫法以实际宿主为准。用户属性截图显示“整数/浮点数/字符串/组对象”，其中整数的提示包含原开关类型与布尔用途。该样本确认 UI“整数”对应码 1；不要将来源中的“1=开关”理解为只允许 0/1。记录类型时同时保留 UI 名称和原始数值，其他类型映射需各自验证。

## 绑定已有证据与未决问题

一个装配样本的四条已绑定通道，在连续四字符串 `[通道名, 变量名, '', '']` 后，首 u32 等于对应变量自身 ID，第二 u32 等于其类型码；四组均匹配，变量尾块 +16 都是 1。新增的那个未绑定变量在该位为 0，另一原生样本的内建对象也可为 1。因此它暂称引用状态候选，不能说是引用次数、通道专用标志或绑定目标 ID。

通道条目的完整布局仍按驱动与类型判定；上述关联不证明任意新地址注册或字节新增可用。继续遵循 [通道边界](device-channels.md)。窗口输入、脚本和设备绑定分别取证，不能互相代替。

若 ID 出现 `[0,2,3]`，按记录数 3 追加就会与已有 3 冲突；本次内存负例也证实连续 ID 解析器在缺少 1 时提前结束。这是算法前提反例，不是原生删除语义的实测。

## 最小后续实验

同一模板依次无修改另存、新增 A/B/C，各步保存；再单独加入一个绑定 C 的输入框、删除 B、新增 D、同控件改绑 D、关闭重开另存。四个测试变量使用相同 UI 类型和初值，其他属性固定。保留绑定前的 C 阶段，可同时观察变量新增与后续引用变化，减少重复分支。

分别核对实际存储 ID、头部计数、记录删除/保留、引用状态候选及同一输入框的名称/ID。最后另行检查属性、Ctrl+E、离线输入及持久化。尚未完成删除/再新增之前，不添加任意变量分配规则，不把第三方 builder 合并为正式写入入口。
